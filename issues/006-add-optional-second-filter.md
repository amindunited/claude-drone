# 006 — Add optional second filter (series) per voice

> *This was generated by AI during triage.*

**Category:** enhancement · **State:** ready-for-agent

## Background

Each voice currently has exactly one `BiquadFilterNode`
(`note-voice.ts:71-75`, `this.filter`) driven by `filterType` / `cutoff` /
`resonance` / `envDepth`, wired `src -> filter -> amp -> voice.bus`. The
maintainer confirmed the second filter should be wired in **series** after
filter 1, with its own full parameter set, defaulting to disabled so
existing patches are unaffected.

Confirmed via triage: no `filter2`/dual-filter code exists anywhere in
`drone-synth/src`, so this is new work.

## Scope

- Add to `VoiceParams` (`types.ts`) and `DEFAULT_VOICE_PARAMS`
  (`constants.ts`): `filter2Enabled` (default `false`), `filter2Type`
  (`FilterType`, default `'lowpass'`), `filter2Cutoff`, `filter2Resonance`,
  `filter2EnvDepth` — same defaults/ranges as their filter-1 counterparts.
- In the `NoteVoice` constructor (`note-voice.ts:70-84`), always create a
  second `BiquadFilterNode` (`filter2`) — same pattern this codebase
  already uses for LFO2, which is always instantiated and only
  conditionally connected/audible (`_createLfo`, `note-voice.ts:113-127`).
  A disabled filter must be a real bypass (`filter -> amp` directly), not
  a "neutral" filter setting — a biquad filter is never fully transparent,
  so leaving it in the chain with inert-looking params would still color
  the sound.
- Give filter2 its own envelope-depth modulation. Reuse the existing
  `fenv` `ConstantSourceNode` (`note-voice.ts:77-84`) feeding a second,
  independent `fenv2Gain` node into `filter2.frequency` — the envelope
  shape is shared across both filters, only the depth differs, so a
  second `ConstantSourceNode` should not be needed.
- Update `updateLive()` (`note-voice.ts:170-187`) to retune filter2's
  type/cutoff/resonance/envDepth, and to re-route the bypass connection if
  `filter2Enabled` is toggled while a note is sounding.
- Update `release()`, `forceStop()`, `_cleanup()`
  (`note-voice.ts:189-262`) to stop/disconnect filter2's associated nodes.
- Add UI: a second collapsible "Filter 2" section in
  `Voice._buildPanel()` (`voice.ts`), following the existing LFO2
  collapsible-section pattern (`data-section="lfo2"` /
  `toggle-lfo2`, `voice.ts:191-213`) for visual/structural consistency,
  with an explicit enable toggle (filters have no natural "off" type, so
  this can't reuse the LFO's `target: 'none'` trick) plus the same three
  knobs filter 1 has (`CUTOFF` / `RESO/Q` / `ENV DEPTH`).

## Explicit constraints

- `normalizeVoiceSettings` (`persistence.ts:87-99`) will backfill
  `filter2Enabled: false` for existing presets via its `Object.assign`
  merge — no bespoke migration code needed.
- Keep the two filters' parameter sets independent; do not add
  cross-filter linking/blending controls — that's a different feature.

## Acceptance criteria

- Voices with `filter2Enabled: false` (default, all existing presets) are
  audibly and structurally unchanged (verify the bypass path truly skips
  `filter2`, not just zeroes its effect).
- Enabling filter2 audibly applies a second filter stage in series after
  filter1, independently configurable.
- Toggling filter2 on/off live re-routes without introducing clicks/pops
  beyond what this codebase's existing `setTargetAtTime` ramping already
  produces elsewhere.
- No orphaned `AudioNode`s on release/force-stop.
- `tsc` passes with no type errors.
- Manual smoke test: no regression for existing voices; correct
  series-filter behavior when filter2 is enabled; a preset saved with
  filter2 configured round-trips through save/load unchanged.
