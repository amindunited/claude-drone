# 008 — Add per-voice note-trigger offset (fixed seconds or tempo-synced)

> *This was generated by AI during triage.*

**Category:** enhancement · **State:** ready-for-agent

## Background

`Voice.noteOn()` (`voice.ts:52-60`) synchronously constructs a `NoteVoice`
the instant a key is pressed (`keyboard.ts`'s `triggerGlobalNoteOn` →
`voices.ts`'s `globalNoteOn` → `Voice.noteOn` for every voice). There is no
per-voice trigger delay today.

This repo already has a UI/data convention for "a raw value OR a
tempo-synced division" — `LfoRateMode` (`'hz' | 'sync'`, `types.ts:4`),
wired via the `.toggle-pill` rate toggle + conditional division `<select>`
in `voice.ts:180-186, 257-269`, resolved to a real time value via
`Engine.divisionHz()` (`engine.ts:91-93`) and `LFO_DIVISIONS`
(`constants.ts:11-22`). The new note-offset control should follow this
same shape rather than inventing a new pattern.

Per maintainer direction, this is a **per-voice trigger delay**: when a key
is pressed, a voice's note onset can be delayed by a fixed number of
seconds, or by a tempo-synced division — letting voices in a chord
stagger like a strum, rather than a global note-start quantizer.

## Scope

- Add `noteOffsetMode: 'seconds' | 'sync'`, `noteOffsetSeconds: number`,
  `noteOffsetDivision: number` to `VoiceParams` (`types.ts`) and their
  defaults to `DEFAULT_VOICE_PARAMS` (`constants.ts`) — default
  `noteOffsetMode: 'seconds'`, `noteOffsetSeconds: 0`, so all existing
  patches trigger instantly, unchanged.
- In `Voice.noteOn()` (`voice.ts:52-60`), resolve the offset to seconds
  (0 for `seconds` mode at value 0; `1 / Engine.divisionHz(noteOffsetDivision)`
  for `sync` mode) and, when non-zero, delay `NoteVoice` construction via
  `setTimeout` (consistent with this codebase's existing scheduling style,
  e.g. `note-voice.ts:223`) instead of creating it immediately.
- Handle the pending window in `Voice`:
  - If `noteOff(note)` (`voice.ts:62-69`) fires before the delayed
    `NoteVoice` has been created, cancel the pending timer instead of
    creating a still-born voice that immediately releases.
  - If `noteOn` fires again for the same note while a previous trigger for
    that note is still pending, cancel the old timer before scheduling the
    new one — extend the existing `activeNotes.has(note)` force-stop-and-
    replace handling (`voice.ts:54-56`) to also cover "pending, not yet
    started."
- Add UI: a "Note Offset" control group in `Voice._buildPanel()`
  (`voice.ts`), reusing the existing seconds/sync `.toggle-pill` +
  conditional division `<select>` pattern from the LFO rate control, plus
  a seconds knob (~0–2s range) for the non-synced case.
- `updateLive()` must **not** retroactively reschedule a note that has
  already started sounding — offset only affects the moment of trigger,
  the same way attack/decay envelopes aren't rewound mid-note when their
  params change.

## Explicit constraints

- No BPM-during-flight rescheduling: a pending sync-mode offset uses the
  BPM at the moment the key was pressed; if BPM changes while the offset
  is still pending, the already-scheduled `setTimeout` does not get
  rewound. That refinement is out of scope for this ticket.
- `normalizeVoiceSettings` (`persistence.ts:87-99`) backfills the new
  fields for existing presets automatically via its `Object.assign` merge
  — no bespoke migration code needed.

## Acceptance criteria

- With the default `noteOffsetMode: 'seconds'` / `noteOffsetSeconds: 0`
  (all existing presets), notes trigger with no perceptible delay —
  matches current behavior exactly.
- Setting one voice's offset to e.g. `0.3s` while another voice in the
  same patch has no offset, then playing a chord, audibly staggers when
  each voice's note begins.
- Setting a voice's offset to `sync` mode with a division (e.g. "1/8")
  staggers note onset by a tempo-relative delay.
- Rapidly pressing and releasing a key before its offset elapses does not
  produce a note that starts anyway after release.
- Rapidly re-triggering the same note while a previous trigger for that
  note is still pending does not produce a doubled/overlapping voice.
- `tsc` passes with no type errors.
- Manual smoke test: no regression for un-offset voices; correct
  staggering behavior across a multi-voice patch in both `seconds` and
  `sync` modes.
