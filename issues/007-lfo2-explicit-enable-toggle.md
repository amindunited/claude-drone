# 007 — Add explicit enable/disable toggle for LFO 2

> *This was generated by AI during triage.*

**Category:** enhancement · **State:** ready-for-agent

## Background

A second LFO already exists end-to-end: `lfo2Target` / `lfo2RateMode` /
`lfo2RateHz` / `lfo2RateDivision` / `lfo2Depth` in `VoiceParams`
(`types.ts`, `constants.ts`), a full UI section in `Voice._buildPanel()`
(`voice.ts:191-213`), and audio wiring via `_createLfo('lfo2', p)` in
`NoteVoice` (`note-voice.ts:94-96, 113-127`). Confirmed via triage: this is
**already implemented and already optional** in the sense that
`lfo2Target: 'none'` disconnects its depth gain from any target.

However, `_createLfo` (`note-voice.ts:113-127`) unconditionally creates and
starts an `OscillatorNode` + `GainNode` for LFO2 on *every* note-on, and
registers it in `Engine.syncedLfos` (`engine.ts:60`), even when the voice
never uses it. Per maintainer direction, this ticket adds a real
enable/disable flag (rather than relying on `target === 'none'`) and skips
allocating the LFO2 oscillator/gain node entirely when disabled.

## Scope

- Add `lfo2Enabled: boolean` to `VoiceParams` (`types.ts`) and
  `DEFAULT_VOICE_PARAMS` (`constants.ts`), default `false`.
- **Backward-compat rule for existing saved patches:** `normalizeVoiceSettings`
  (`persistence.ts:87-99`) currently merges saved params over
  `DEFAULT_VOICE_PARAMS` via `Object.assign`, which would silently disable
  LFO2 on any preset saved *before* this change that already uses it
  (`lfo2Target !== 'none'`). Add an explicit normalization rule: if a
  loaded voice has no `lfo2Enabled` field but `lfo2Target !== 'none'`,
  default `lfo2Enabled` to `true`; otherwise `false`.
- In `NoteVoice` (`note-voice.ts`), make `lfo2` nullable/optional and only
  call `this._createLfo('lfo2', p)` when `p.lfo2Enabled`. Guard all
  `this.lfo2.*` usages in `updateLive()` (`:170-187`), `release()`
  (`:189-224`), `forceStop()` (`:226-248`), and `_cleanup()`
  (`:250-262`) accordingly — mirror the existing conditional style already
  used for LFO target changes (e.g. `if (this.lfo1.target !== p.lfoTarget)`).
- If `lfo2Enabled` is toggled off while a note is currently sounding, tear
  down the live LFO2 oscillator (stop + disconnect + remove its entry from
  `Engine.syncedLfos`) rather than just disconnecting its depth gain, so no
  silent oscillator keeps running.
- Add an explicit enable toggle to the "LFO 2 / Modulation" panel section
  (`voice.ts:191-213`), using the same `.toggle-pill`/icon-button visual
  language already used elsewhere in this panel.

## Acceptance criteria

- With `lfo2Enabled: false` (new default), no LFO2 `OscillatorNode`/
  `GainNode` is created on note-on, and `Engine.syncedLfos` never gains an
  LFO2 entry for that voice.
- Autosave/presets saved *before* this change that already used LFO2
  continue to sound identical after this ships (verify the backward-compat
  rule above with a pre-change preset fixture, or by hand-editing an
  autosave entry that lacks `lfo2Enabled`).
- Toggling LFO2 on/off from the UI, including while notes are held or
  re-triggered, leaves no leaked audio nodes.
- `tsc` passes with no type errors.
- Manual smoke test of LFO2 target/rate/depth controls confirms parity
  with pre-change behavior when enabled.
